# Hash Tool Suite — Non-AI Framework

I’m treating **Hash Tool Suite** as a professional, privacy-first collection of hashing, checksum, HMAC, comparison, encoding, and verification utilities.

The important finding from the research is that this is an excellent fit for the non-AI framework: modern browsers expose cryptographic primitives through the Web Crypto API, including SHA-1, SHA-256, SHA-384, SHA-512 and HMAC; hashing can therefore be performed locally without uploading user data. ([MDN Web Docs][1])

MD5, SHA-1, SHA-3, BLAKE-family algorithms and some other legacy/non-Web-Crypto algorithms require a client-side implementation/library if included. MD5 and SHA-1 should be explicitly marked **legacy/insecure for security purposes**, while retaining them for compatibility and checksum use cases. ([MDN Web Docs][2])

# 19. Algorithm Abstraction

The UI should never directly depend on a specific cryptographic implementation.

```text
HashEngine
│
├── SHA256Provider
├── SHA384Provider
├── SHA512Provider
├── SHA1Provider
├── MD5Provider
├── SHA3Provider
├── BLAKE2Provider
└── CRCProvider
```

Each provider exposes the same conceptual interface:

```text
input
algorithm
encoding
outputFormat
↓
digest
```

This allows algorithms to be added without rebuilding the UI.

# 20. Large File Architecture

This matters.

A 4 GB ISO should **not** require loading the entire file into memory.

Use:

```text
File
│
▼
Readable Stream / Chunks
│
├── Chunk 1
├── Chunk 2
├── Chunk 3
├── ...
└── Chunk N
│
▼
Incremental Hash Engine
│
▼
Digest
```

However, the native `SubtleCrypto.digest()` API itself does not provide streaming digest updates; it takes the complete data buffer. ([MDN Web Docs][2])

Therefore:

* use native Web Crypto for manageable buffers;
* use a client-side incremental implementation/WASM provider for genuinely large files;
* process work in Web Workers;
* never block the main UI thread.

# 27. Security UX

A critical design requirement:

**Never imply that hashing is encryption.**

The application should clearly distinguish:

```text
HASHING
One-way digest
```

from:

```text
ENCRYPTION
Reversible with a key
```

and:

```text
HMAC
Keyed integrity/authentication
```

This distinction belongs directly in the UI, not buried in documentation.

```text

│

│
```

Benefits:

* UI remains responsive
* Large files do not freeze the application
* Multiple files can be processed
* Progress can be displayed

# 37. Critical Boundary

### Included

**Research → Capability Classification → Browser Feasibility → Hash Tool Taxonomy → Crypto Abstraction → File Architecture → Desktop UI → Mobile UI → Gestures → Haptics → Performance Architecture → Storage → Export**

### Explicitly excluded

* AI
* LLM
* Cloud hashing
* Server hashing
* Remote processing
* Password-cracking functionality
* Hash-reversal services
* Rainbow-table infrastructure
* Brute-force cracking engine
* Distributed cracking
* GPU password cracking

The suite is fundamentally a **local hashing, integrity, checksum and cryptographic utility workspace**, not a password-cracking platform.
