# Barcode & QR Suite

## Research → Capability Classification → Architecture → Responsive UI → Interaction Specification

## 0. Objective

Design a professional, privacy-first **Barcode & QR Suite** capable of:

* Creating QR codes
* Creating 1D barcodes
* Creating 2D barcodes
* Scanning codes using the camera
* Scanning uploaded images
* Reading codes from screenshots/photos
* Managing decoded results
* Creating printable labels
* Generating serial/batch codes
* Converting structured information into codes
* Exporting codes in professional formats
* Providing barcode/QR diagnostics
* Supporting offline/browser-native workflows wherever technically practical

The suite must feel like a professional utility application rather than a collection of unrelated generators.

The primary design principle is:

**The code/result is the center of the workspace; tools surround it contextually.**

Do not begin algorithm implementation during this phase.

# PHASE 2 — BROWSER-NATIVE VS SERVICE-DEPENDENT CLASSIFICATION

Every capability must be classified into one of three groups.

## A. Browser-native

These should operate without a server wherever practical.

Examples:

* Static QR generation
* Static barcode generation
* Text → barcode
* Number → barcode
* URL → QR
* vCard → QR
* Wi-Fi → QR
* Contact → QR
* Email → QR
* Phone → QR
* SMS → QR
* Calendar → QR
* Location → QR
* Image-based barcode decoding
* Camera-based scanning
* Screenshot scanning
* Clipboard scanning
* Local file scanning
* Batch generation
* Serial-number generation
* Code validation
* Code preview
* Code customization
* SVG export
* PNG export
* print layout generation
* local scan history
* local project storage
* local templates
* local presets

## B. Browser + optional local/embedded processing

Potentially browser-native but may require specialized libraries, WASM, Web Workers, or device capabilities.

* Multi-format decoding
* Perspective correction
* difficult-image scanning
* low-light enhancement
* damaged-code recovery
* document/camera preprocessing
* image denoising
* automatic crop
* automatic orientation detection
* high-speed continuous scanning

The architecture must permit these capabilities without forcing a server dependency.

## C. Backend/service-dependent

These should NOT be falsely represented as offline features.

* Dynamic QR redirect
* QR destination editing after distribution
* Hosted file QR
* Scan analytics
* Geographic scan analytics
* device analytics
* campaign tracking
* cloud scan history
* multi-user projects
* team collaboration
* cloud asset storage
* remotely managed QR codes
* URL shortening
* server-side redirects
* authentication
* enterprise synchronization

Important:

**A "file QR code" has two distinct meanings.**

### Local file encoding

The file/data itself is encoded into a suitable code where technically possible.

This is browser-native but limited by the code's data capacity.

### Hosted file QR

The QR contains a URL pointing to a file hosted somewhere.

This requires hosting/storage and therefore belongs to the optional service layer.

Never confuse these two concepts in the UI.

# PHASE 12 — HAPTIC SYSTEM

If haptics are unavailable, the interface must remain completely functional.
