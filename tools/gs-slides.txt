# Presentation / PPT Suite — Non-AI Research, Architecture & UI Framework

## 0. Product Definition

The product is a **professional, local-first presentation editor**.

Its purpose is to let a user create, edit, design, animate, present, import, and export presentations **without AI, cloud processing, or server-side inference**.

### Core principle

> **Everything in the core suite is deterministic and executable in the browser.**

```text
USER
│
▼
PRESENTATION WORKSPACE
│
├── Slide Editor
├── Object Editor
├── Layout System
├── Typography
├── Charts & Tables
├── Diagram System
├── Media System
├── Animation System
├── Theme System
├── Presentation Mode
└── Export System
│
▼
LOCAL BROWSER ENGINE
│
├── Rendering
├── Document Model
├── Interaction
├── History
├── Storage
└── Export
```

# 1. Phase One — Presentation Suite Research

The suite should combine the strongest **non-AI** capabilities found across professional presentation and design software.

The reference capability groups are:

* PowerPoint / Impress-style presentation editing
* Keynote-style presentation and animation workflows
* Figma-style object manipulation
* Canva-style template and design workflows
* Vector-editor-style geometry and alignment
* Spreadsheet-style tables and data visualization
* Professional presenter tools

The objective is **not to copy their interfaces**.

It is to identify the underlying capabilities and build a unified architecture.

# 33. Haptic Feedback

Haptics are semantic.

### Light tap

Selecting a tool.

### Tick

Snapping / grid increments.

### Pulse

Object reaches alignment.

### Double pulse

Successful duplication.

### Boundary feedback

Object reaches slide boundary.

### Warning

Invalid operation.

Haptics gracefully disable on unsupported hardware.

# 41. Performance Architecture

Because everything is local, performance becomes a primary engineering concern.

### Use

* Web Workers for expensive operations
* OffscreenCanvas
* GPU-accelerated rendering where useful
* Virtualized slide thumbnails
* Lazy-loaded assets
* Incremental rendering
* Dirty-region rendering
* Object caching
* Thumbnail caching
* Debounced persistence
* IndexedDB

### Avoid

* Re-rendering the entire presentation for every mouse movement
* Loading every asset at startup
* Keeping large image copies unnecessarily
* Converting everything into raster images
* Making the DOM responsible for thousands of canvas objects

## STOP CONDITION

The framework stops here.

**No AI. No LLM. No model inference. No backend AI service. No cloud AI.**

The finished specification is:

> **Research → Non-AI Capability Map → Browser-Only Classification → Tool Taxonomy → Document Architecture → Rendering Architecture → Desktop UI → Mobile UI → Gestures → Haptics → Interaction System → Responsive Architecture → STOP**

The next phase, separately, would be **algorithm and implementation engineering**: rendering, scene graph, object transforms, chart engine, animation engine, PPTX serialization, PDF generation, import parsing, local persistence, and the rest of the actual implementation.
